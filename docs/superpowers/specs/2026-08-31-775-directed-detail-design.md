# #775 Directed surface detail — design

Date: 2026-08-31. Ticket: #775 (depends on #770, Resolved). Approved in chat:
pixels-in-the-map mechanism, height→bump relief, new tool consuming #770's
bakes.

## Purpose

The toolbox's surface detail today is undirected — `displace_noise` and
`noise_bump` apply everywhere equally, which reads as "textured plastic".
Real detail follows the form: wear on edges, grime in pockets, grain
modulated by both. #770's baked curvature and AO maps are exactly those
masks as real image files, so directed detail becomes arithmetic on maps.

**Decision recorded from the design conversation:** the deliverable of this
repo is the exported FBX, which carries only file textures — so a
shader-network implementation would have to be baked to pixels before
export anyway and can never ship more quality than the pixel route; it
only adds the #714 constant-channel risk class. Detail therefore lives in
**pixels**, generated by our own Python in the same UV space as the masks
(correlation exact by construction). Relief ships as a generated **height
map wired as file-backed bump** — true Arnold displacement is render-only
and would silently vanish from the FBX, which is the worst kind of
quality: the kind that is not there when it ships.

## Tool surface

`maya_apply_surface_detail` — one new wire command `apply_surface_detail`,
handler `maya_plugin/handlers/surfdetail.py` (+ pure-math module
`surfdetail_math.py` for the pattern generators and compositing, testable
headlessly).

Params:

| param | type | default | meaning |
|---|---|---|---|
| `mesh` | str | required | one mesh per call (matches the per-mesh map files) |
| `maps_dir` | str | required | absolute dir where #770 wrote the bakes; the tool locates `<shortname>_ao.png` / `<shortname>_curvature.png` |
| `out_dir` | str | `maps_dir` | where composites and the height map are written |
| `effects` | list | required, non-empty | each `{kind, strength?, scale?, color?}` |
| `resolution` | int | mask resolution | output size, must be in `texbake.RESOLUTIONS` |
| `seed` | int | 0 | deterministic pattern variation |

Effect kinds (each kind at most once per call — repeating a kind refused):

- **`wear`** — mask = curvature (convex). Scratch/chip pattern (ridged,
  thresholded fbm) multiplied by the mask, composited into the colour map
  as a lightening/tint toward `color` (default: a lightened base — worn
  paint showing substrate). `strength` scales opacity, `scale` the
  pattern frequency.
- **`grime`** — mask = inverted AO. Speckled low-frequency fbm times the
  mask, composited as a darkening multiply toward `color` (default dark
  brown-black). Same knobs.
- **`grain`** — writes the **height map**, does not touch colour. Height =
  fbm amplitude modulated by a blend of curvature and inverted AO (worn
  edges roughen, pockets crust). Wired `file → bump2d(bumpInterp=0,
  outAlpha→bumpValue) → shader.normalCamera` — the measured pbr.py idiom
  with the interp that means height, not normal map. `strength` maps to
  `bumpDepth`.

When both colour effects are requested they composite in a fixed order —
wear first, grime over it (grime settles on top of worn paint; the order
is the tool's, not the caller's list order, so results are
order-independent for the caller). Colour compositing runs through #770's
machinery: sRGB-decode → linear blend → re-encode, written to a NEW file `<mat>_color_detail.png` via the
`.part.png` → `os.replace` commit; the input file is never overwritten.
Rewire uses meshmaps' `_rewire_color` shape; the whole apply is one
checkpoint (`session.auto_checkpoint`), failed builds sweep exactly their
own nodes, and `texclaim.material_claims` is the postcondition.

## Refusals and warnings

Refused (validate-time, `require_known_keys` + synonyms on the tool and on
each effect dict):

- unknown effect kind, empty effects list, a kind repeated;
- required mask file missing for a requested effect (message names the
  exact path looked for and hints `maya_bake_mesh_maps`);
- **flat mask** — a uniform curvature/AO map cannot direct anything; the
  refusal states the measured distinct-value count. This is deliberately
  stricter than #770 (where flat maps WARN, because a flat bake can be
  honest): a flat mask makes *this* tool's whole claim false.

Not refused: mask resolution ≠ colour-map resolution — handled by
nearest-neighbour sampling in UV space (masks and colour maps share the
mesh's UV layout, so normalized texel centres correspond).
- the base-colour situations #770 already refuses (procedural base →
  hint `maya_bake_textures`, multi-SG, non-PNG file base).

Warned, not refused: an effect whose composite changed fewer than 0.5% of
pixels ("strength/scale produced almost nothing — likely too low a
strength or too tight a threshold").

## Gate — the ticket's three-part claim, measured

`evals/surfdetail_live.py`, agent Maya on 9878, scene reuses the
meshmaps_live geometry class (ground + limb + collar, native UVs):

1. **Masks non-uniform** — asserted from the #770 bake stats.
2. **Correlation, the word "directed" as a number** — for wear: mean
   detail delta (|after−before| per texel of the colour map) over texels
   in the top mask quartile vs bottom quartile; ratio must exceed a bar
   set by a probe (expected ≥ 3×, pinned after measurement). Same for
   grime against inverted AO, and for the height map against its blend
   mask. This is computed by the gate from the actual files, not trusted
   from the tool's own report.
3. **Render differs** — before/after `render_scene` mean-luma delta plus
   a pixel-difference count; bars pinned after the first honest run
   (#770's lesson: relative bars on dark frames).
4. **Ships** — export with `require_baked_textures=True`; composite and
   height basenames present in the FBX bytes; `dropped_maps` empty.

Renders from both sides are saved for eye judgment — a correlation number
cannot see "looks like mould, not wear".

## Probes before implementation (plan step 1)

- **P1 perf**: pure-Python fbm at 1024² is ~2M+ `vnoise` calls; measure.
  If over ~15 s, generate at quarter resolution and bilinearly upsample
  the *pattern* (the mask stays full-res) — pattern smoothness is not
  where the direction lives.
- **P2 bump export**: build file→bump2d(interp 0)→standardSurface in a
  real Maya, export, confirm texclaim classifies it file-backed and the
  FBX carries the PNG name. pbr.py's idiom is measured for normal maps
  (interp 1); interp 0 through the same path is asserted, not yet
  measured.
- **P3 look probe**: render one wear and one grime composite on the gate
  geometry and LOOK before pinning pattern constants (threshold, octave
  count, default colours). Constants chosen by eye, then frozen into the
  handler with the probe recorded.

## Out of scope (per ticket + conversation)

True Arnold `displacementShader` (render-only, doesn't ship in FBX);
sculpted/anatomical detail (pores, cloth folds); generated displacement
sources; multi-mesh batching (one mesh per call — callers loop);
UV-overlap detection (the #770 follow-up, unfiled).
