# #823 — set_camera, group and capture back, gated functionally for the first time

Redmine #823, fifth item of the #818 audit: `set_camera` and `group` had been
reached only by refusal sweeps; `capture_viewport angle=back` had never been
sent by a gate. Probe (kept): `evals/item5_probe_823.py`; findings and the
captures under `evals/item5_probe_823/`. Maya 2027, agent 9878, repo cwd.

## What held

- **set_camera aims exactly.** The camera's forward axis (world −Z of its
  matrix) against the unit vector to `look_at` reads 1.000000 from (0,0,10),
  (10,0,0), (0,10,0), (5,5,5), (−3,2,−7) and (0,−6,0.001) at an off-origin
  target. `focal_length` lands on the shape; `set_active` true/false is
  measured on the panel; `camera="persp"` moves Maya's own camera; a call
  with no params reuses and activates. Pixel test: red cube at +Z, blue at
  −Z; set_camera at +Z then `capture_viewport angles=["current"]` → 1444
  red px / 0 blue; at −Z → 0 / 1444.
- **capture back is the back.** front → 14884 red / 0 blue; back → 0 /
  14884; side and top ≈ equal. The back camera sits at z = −4.57 with
  rotation [0, 180, 0]. No temp camera survives the call.
- `group` reparents with world transforms preserved, nests, and a member
  whose parent was rotated gets its local transform rewritten correctly.

## What was measured and fixed

- **set_camera `focal_length` 0 / negative** reached `setAttr`, which raised
  Maya's raw "Cannot set the attribute 'mcpCamShape.focalLength' below its
  minimum value of 0.5" — after the position write had landed (half-applied,
  the #802 shape). Now validated before any write: a number ≥ 0.5 mm, else a
  hinted refusal with nothing moved. A numeric string is refused too.
- **`group` said nothing about the pivot it made.** `cmds.group` builds the
  transform at the origin with identity but puts its rotate pivot at the
  members' bounding-box centre: cubes at x=2 and x=4 grouped, group rotated
  90° about Y → the members orbit (3,0,0). The result now carries `pivot`
  (queried back) and `children` (new canonical paths, in the order given),
  and `pivot: "origin"` (combine's word) puts the pivot at the world origin
  first — the rig case from #814.
- **Silent renames lost ledger tracking.** Two members named `part` from
  different parents: Maya renames the second `part1`; the ledger re-key
  matched by short name, so both old entries mapped onto `|parts|part` and
  `part1` was never recorded. Members are now matched by UUID (`cmds.ls
  uuid=True` before, `cmds.ls <uuid> long=True` after) and the rename is a
  warning.
- **Other quiet things, now warnings:** a `group_name` already held
  (`|taken` → `|taken_001`, as `boolean_op` already warned), a duplicate
  entry in `names` (Maya dedupes), and a former parent left empty.

## Noted, not fixed

- `rotation` in set_camera's result is Maya's euler readback and can be an
  equivalent triple ([166.8, −38.7, −180] for a camera at (−3,2,−7)); the
  aim is right, the numbers are Maya's. Documented.
- `capture_viewport back` with `target=|red` frames the target from behind
  the blue cube, so the frame is 100 % blue, `blank: false`, no warning: a
  target framed from behind another object is occluded; `isolate` is the
  tool for that. Detecting occlusion would need an id pass.
