# #767 Param-Validation Sweep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every registered plugin command refuses an unknown top-level `params` key with a named, hinted error instead of silently ignoring it — plus the four code-level minors queued to #767 from #770/#771/#775.

**Architecture:** Per-handler literal `<CMD>_KEYS` tuples + `require_known_keys()` as the FIRST statement of each handler (the established #764 idiom, `material.py:176-188`). Maintenance risk (a missed key = runtime refusal of a legitimate caller) is closed by two headless meta-tests instead of runtime derivation: (1) a parametrized refusal test over `_build_handlers()` proving every command refuses an unknown key, and (2) an AST drift test proving every key the MCP wrapper in `src/maya_mcp/server.py` can send is accepted by the handler's tuple. Key tables below were extracted by a fan-out over every handler module and adversarially verified by independent re-derivation (workflow `wf_67b71019-31a`).

**Tech Stack:** Python (Maya plugin, no Maya needed for the guard path), pytest headless (`uv run pytest`), mayapy suite (`mayapy -m pytest tests/test_handlers_mayapy.py`), live gate via agent Maya on port 9878.

**Spec:** Redmine #767 (http://localhost:3000/issues/767) — the ticket body IS the spec. Queued minors per memory backlog 2026-09-01.

The parser tracks `params = {...}` literals plus subsequent `params["k"] = ...` additions inside the same function; any second-arg shape it cannot resolve is a test failure naming the wrapper (a new dynamic pattern must be looked at, not skipped).
